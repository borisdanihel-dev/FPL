## The 3 surviving mutants of 42 (WARN ruling, point 3)
1. **The frozen value by `three_layer_terms(pos)`:** no longer surviving.
   - Red on `f1c3704` (both forms of mutant 2, and an xgi + cs variant).
2. **`xi_key` called and its result ignored, XIs compared by float sums**
   (`worklog/checkpoint_gw10/checkpoint.py`): it **can** change behaviour.
   - When two legal XIs tie as written decimals but not as binary floats
     (e.g. 0.1 + 0.2 against 0.3), the float order picks one, where the GW15
     rule breaks the tie by the id list.
   - The verifier found 0 XIs changed in 9,000 random squads (1,750 with a tie
     at the top).
3. **`val = Fraction(float(v))`** in place of `_exact` (the same file): it
   **can** change behaviour, for the same reason.
   - Exact binary sums separate decimal ties, so the id rule is never
     reached for them.
   - 0 XIs changed in 9,000 random squads.

Both live in the offline checkpoint tool that the GW15 tie rule uses, not in
the runner. As the ruling directs, they are parked as a new question (below);
it does not block tonight.
