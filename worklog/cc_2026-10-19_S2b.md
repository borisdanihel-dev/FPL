## What was built

- **`fpl_sync.py`, the first sight** (point 1). `events.data_checked_seen_utc`
  is added by SCHEMA and by ALTER TABLE, NULL for stored rows. The nightly
  rewrite of `events` is now an upsert:
  - `INSERT ... ON CONFLICT (id) DO UPDATE` keeps every other column current;
  - `COALESCE(events.data_checked_seen_utc, excluded.data_checked_seen_utc)`
    keeps the first sight. That is the bootstrap fetch time of the first sync
    that saw `data_checked = 1`, never changed after, not even when
    data_checked reads 0 again.
- **`fpl_sync.py`, finality** (point 1). `is_final(db, table, gw, entry)`:
  - True only when the event's first sight is set, the table holds rows for
    that gameweek (and entry), and every row's `fetched_at_utc` is strictly
    later than the first sight;
  - NULL or an unreadable time is never final.
  - `sync_player_gw` re-fetches every gameweek that is not final; the old
    `finished` test is gone. The `--refetch` and "301+ rows" guards stay.
  - `sync_entries` re-fetches an (entry, gameweek) unless both its entry_gw
    and its picks are final.
  - `picks` gets `fetched_at_utc` (SCHEMA and ALTER TABLE, NULL for stored
    rows), written with the entry_gw row's time.
- **`checks.py`, check 22** (point 2):
  - every started gameweek that `gameweek_settled` accepts is reconciled, not
    only the latest;
  - every mismatch is listed (GW, entry, FPL against computed), none cut, and
    any makes a WARN;
  - the latest gameweek, if not locked down, is named "silent mid-gameweek"
    (S3, point 6).

## Decisions for the chat

1. `automatic_subs` rows are added on a re-fetch, never deleted. A
   provisional substitution FPL later withdrew would stay. None was seen (the
   rehearsal added 14 rows and dropped none).
2. A row fetched in the same second as the first sight is not "later", so it
   is fetched once more the next night. That costs one extra call; it is
   never wrong.
3. "WARNs per mismatch" is built as one check-22 WARN that lists every
   mismatch.
