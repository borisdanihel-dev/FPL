## What was built

- **`nightly.yml`:**
  - `on: push: branches: ["dry/**"]` and nothing else (point 1);
  - `run-name: dry run <ref>` for every dry run, pushed or manual, so the cap
    can count them;
  - `actions: read` added to the one job (point 4);
  - `GH_TOKEN` for the due step;
  - both `ODDS_API_KEY` lines are `''` on a push (point 2). The concurrency
    expression is unchanged: a push's ref is never master, so its group is
    `nightly-dryrun`.
- **`fpl_publish.py`** (point 3):
  - `result_branch`: `data-dryrun-<item>` for a push to `dry/<item>`,
    `data-dryrun` otherwise;
  - `dry_target`, and `push_dry(branch)`, which refuses anything else, `data`
    above all, without a git call.
- **`fpl_dryrun.py`** (new, stdlib), the gate. It skips green, with a
  `DRY RUN SKIPPED:` line:
  - from 21:30 UTC until the data branch has a commit at or after it, 03:17
    UTC at the latest (point 5, reading b);
  - within 1 hour either side of a deadline;
  - at 6 dry runs that UTC day, pushed and manual together (point 4, reading
    a), counted with the Actions API: a run counts once its "Nightly run"
    step has started; this run is left out;
  - when it cannot count.
- **`fpl_nightly.py --due`:** runs the gate for every dry run, never for a
  real run.
- **`CLAUDE.md`, `BUILD_PLAN.md` Part E:** the procedure for both lanes.

## Decisions for the chat

1. **Reading (a):** the cap and the windows apply to manual dry runs too.
   Point 4: "together count", "the 7th ends green"; point 6 keeps the
   dispatch's inputs and target.
2. **Reading (b):** the 21:30 window ends at 03:17 UTC at the latest, so a
   failed night cannot block the dry run of its fix all the next day.
3. **GitHub keeps one pending run per concurrency group.** With one dry run
   running, a third push cancels the second while it is still pending. It
   shows as cancelled, not green, and isn't counted; the lane pushes
   `dry/<item>-2`.
4. **Manual dry runs made before W1b lands carry no `dry run` name** and are
   not counted on the landing day.
5. **After a failed night, a push between 03:17 and the backup run's commit
   (about 03:35) runs alongside the backup run** (verifier, reading b). Two
   parallel jobs at most; it is harmless to data, since a dry run writes
   `data-dryrun-*` only. Moving the close to about 04:00 would cover the
   backup run. Say if wanted.
6. **The gate proceeds without a deadline check** if `events` exists but
   holds no deadline row (verifier, minor; theoretical, since data always
   holds 38). A missing or unreadable table already skips. Hardening it is a
   one-line change for the merge day if wanted.
