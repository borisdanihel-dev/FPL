## What was built

- **`fpl_ep`:**
  - `fpl_sync.py` stores FPL's `ep_next` (`players.ep_next`, ALTER TABLE;
    NULL when missing, never 0) and exports it.
  - `fpl_edge.py --record --source fpl_ep` records it for the next
    gameweek, deadline-guarded like every source.
  - No `ep_next` at all gives `RECORD SKIP fpl_ep`, a WARN (check 29).
  - The four frozen sources keep their strict FAIL and record byte-identically.
- **The Odds API collector, `fpl_odds.py`:**
  - one request a night (`soccer_epl`, `h2h,totals`, `uk,eu`, decimal; 4
    credits);
  - the answer body is written byte for byte as gzip (mtime 0, no name) to
    `odds/odds_<UTC>.json.gz` on data;
  - the files are append-only, which the gate checks. There is no SQLite table.
  - `rows()` reads the files and skips `h2h_lay` unless asked.
- **When it calls:** only inside GitHub Actions. A dry run calls only with
  `odds_live` ticked; a real run always calls.
- **The key:** `ODDS_API_KEY` reaches exactly the nightly and commit steps.
  It is never printed or written, and the test suite runs without it.
- **Checks:**
  - check 30 reads the odds line. Every odds problem is a WARN, and so are
    fewer than 60 credits and a missing credit header ("credits unknown").
  - check 24 also WARNs on any data file over 50 MB.
