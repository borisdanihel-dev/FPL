## What was built

- **`checks.py`, the checks.** The 27 checks of the Step 3 table, plus 28 "test gate" and 29 "record" (Amendment 1, point 3).
  - **Inputs:** each reads tonight's database, its last commit (`git show HEAD:`), tonight's run-log block (start time, test result, `SYNC STATS`, record summary), the newest committed run log, the projection log and the working export.
  - **FAIL:** commits nothing, and the run goes red.
  - **WARN:** goes into the status line only.
  - **A check that raises:** a WARN that says so, never a crash.
- **`checks.py`, the status line.** `STATUS OK|WARN|FAIL | generated <UTC> | next deadline GWn <UTC> / <Prague> | checks n/N | repo <MB>`.
  - Prague time comes from `zoneinfo` (ruling 5).
  - The line heads `reports/status.txt` (one line per check follows) and tonight's report.
  - A dry run writes `reports/status_dryrun.txt` and never `status.txt` (ruling 7).
- **`fpl_publish.py`:** a real run whose fresh status says STATUS FAIL commits nothing (Step 3.1). A dry run still reports to `data-dryrun`, so a failed dry run can be read back.
- **`fpl_alert.py`:** the one issue "Nightly run failed" (ruling 3).
  - A red run opens or updates it; the next green run closes it; a duplicate is closed.
  - A dry run never touches it.
  - The workflow grants `issues: write` and `contents: write` only.
- **The 03:17 UTC backup cron** (ruling 4).
  - `fpl_nightly.py --due` gates every step. The run goes ahead only when the last 21:40 slot's nightly left no `status.txt`.
  - It uses the nightly's concurrency group, and the due check writes nothing.
  - The workflow timeout is now 30 min.
- **`fpl_sync.py`** (table row 2):
  - retries only 429, 5xx and network errors, a 403 at most once;
  - waits 0.4 s between calls;
  - prints one `SYNC STATS` line at the end of every sync, even when it stops early. The line carries the core calls' statuses, the element count, ids and key set, teams, fixtures and the required-field report.
- **Actions** (ruling 2): `actions/checkout` v7.0.1 (`3d3c42e5aac5ba805825da76410c181273ba90b1`) and `actions/setup-python` v7.0.0 (`5fda3b95a4ea91299a34e894583c3862153e4b97`). Both are read from their release pages and `git ls-remote`, and pinned in both workflows.
- **Test discovery** (FAST-TRACK item 5):
  - the nightly runs `python -m unittest discover -v -p "test*.py"`, so `test_fpl.py` plus `tests/` (`tests/test_S3.py`);
  - `CLAUDE.md`'s change protocol and local test command say the same.
  - FAST-TRACK item 1's test proves that no root file imports anything under `tools/` or `analysis/`.
- **Hermetic tests** (Amendment 1):
  - `PublishOnAFail` sets its own Git identity;
  - `Hermetic` reruns every git-using test class with an empty home, no system or global Git config and no identity in the environment;
  - `CLAUDE.md` carries the sentence.
