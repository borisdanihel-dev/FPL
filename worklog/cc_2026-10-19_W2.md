## (c) The CHIPS and LEAGUE report sections

- `fpl_chips.py`, `fpl_league.py`, `fpl_bt.py` and `fpl_pit.py` are the
  syntax-tree closure of `tools/chips.py` `live()` and `tools/league.py`
  `report()` (`make_sections.py`), verbatim, with the module aliases kept
  (`BT` → `fpl_bt`, `PIT` → `fpl_pit`). The closure over-approximates: it
  copies 2025/26 helpers the live path never calls.
- **Why a separate step:** both sections need `fpl.sqlite`, which
  `fpl_edge.py`'s report must never open. `fpl_sections.py` runs after the
  report is built, reads the database read-only and appends both sections.
  - A missing input prints `<SECTION> SKIPPED: <why>`; a crash prints
    `SECTIONS FAILED` in the run log.
  - The new check 31 "report sections" WARNs on either and never FAILs;
    the night is never red for it.
- **Real data:** CHIPS (37 lines) and LEAGUE (69 lines) are identical to
  the tools' output on the same folder, seeds and resamples.
