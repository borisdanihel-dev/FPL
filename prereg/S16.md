# S16 part 2 — the 2026/27 calendar mapper

Committed before any code for this item.

- **Item:** S16 part 2 (BUILD_PLAN.md Step 16, point 2; item B1). Offline, under
  `tools/`; the runner never imports it.
- **Hypothesis:** n/a. This is a mapping: each cup date falls in one gameweek
  window, or on a deadline day where the gameweek depends on the kickoff time.
- **Data and sample filter:**
  - the 38 2026/27 deadlines, `events.deadline_time` in `C:\GIT\FPL-data\fpl.sqlite`
    (pulled, opened read-only);
  - the four dates of Step 16.2, all in 2027 (the season's March to May):
    - Carabao Cup final, Sun 21 Mar 2027;
    - FA Cup quarter-finals, Sat 3 Apr 2027;
    - FA Cup semi-finals, Sat 24 Apr 2027;
    - FA Cup final, Sat 22 May 2027.
  - The 2026/27 Premier League fixtures in the same file (`fixtures.kickoff_time`)
    are information only: how many league matches are scheduled that day.
- **Comparison:** none.
- **Primary metric (one):** n/a.
- **Secondary metrics (information only):** league fixtures scheduled on each date.
- **Bootstrap:** n/a.
- **Pass threshold:** n/a.
- **Acceptance tests (descriptive or data-pipeline items, instead of a metric):**
  1. Gameweek g's window is [deadline g, deadline g+1); GW38's window is open
     at the end.
  2. A date is a UK calendar day: midnight to midnight, Europe/London. That is
     UTC+1 from 01:00 UTC on the last Sunday of March to 01:00 UTC on the last
     Sunday of October, UTC+0 otherwise. The rule is coded with no time-zone
     database.
  3. Dates are mapped as follows:
     - A day wholly inside one window maps to that gameweek.
     - A day that contains a deadline is reported as ambiguous between the two
       gameweeks, with the deadline's time. The plan gives dates without
       kickoff times, so the tool never picks a side.
     - A day before GW1's deadline is an error.
  4. Each date's output gives: the gameweek (or the ambiguous pair), the
     deadlines on either side with the hours to each, and the count of 2026/27
     league fixtures that UK day.
  5. Tests in `tests/test_S16.py`, hermetic, with the deadlines frozen in the
     test (no FPL-data). They cover the window rule, the ambiguous day, the BST
     boundary, a date before GW1, the four plan dates on the frozen 2026/27
     deadlines, and the read-only open. One mutation per rule, each red.
  6. Not in this item, parked in `worklog/SESSION_STATE_A.md` for missing inputs:
     - part 1, the history 2016/17-2025/26: only 2025/26 is local;
     - part 3, the cup Monte Carlo: no odds or Elo history, no European
       fixture calendar;
     - part 4, the backtest on 2024/25 and 2025/26.

## Part 1, acceptance tests (committed with the ruling above, before any part 1 code)

Part 1 is a descriptive item. Its acceptance tests:

1. **The tool.** `tools/blank_double.py` is offline, stdlib only, and run with
   `python -I` (downloads are data, never code). For each season with a
   local `historical/<season>/fixtures.csv`, 2018-19 to 2025-26, it counts
   each team's fixtures in each FPL `event`. A blank is 0 fixtures in an
   event, a double 2 or more. Teams are the season's own ids 1-20, and are
   named only where a local `teams.csv` exists (2025-26). There are no
   further downloads.
2. **Unusual events, kept as numbered:**
   - a fixture with no `event` (unscheduled) is counted apart, never placed
     in an event;
   - 2019/20's restart events above 38 are kept as FPL numbered them, and
     flagged.
3. **The reproduction test** (the ruling): for 2024-25 and 2025-26, per team
   and event, the tool's fixture counts equal those counted straight from
   the official fixtures files, exactly. The straight count is a separate
   reader written independently of the tool.
   - Secondary, information only: 2025-26 is checked against a second
     source, the players' fixture rows in `merged_gw.csv`.
4. **Output:**
   - per season, every event with a blank or a double and the teams in it;
   - the season's totals;
   - a cross-season table by event number: how many seasons blanked or
     doubled there, and how many team-events.
5. **Tests:** `tests/test_S16_part1.py`, hermetic, on toy fixtures files:
   - a blank, a double, a triple;
   - an unscheduled fixture;
   - an event above 38;
   - the comparator, which must catch a single changed count;
   - the read-only open.
   One mutation per rule, each red. The suite green bare, runner-like, with
   stand-in zones and hermetically. Then the verifier, the write guard, and a
   green dry run of the landing branch before it lands.
