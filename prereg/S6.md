# S6 — Step 6 (M1, xP rebuild and blend: `xp_v2`)

Committed before any code for this item. Lane B, offline work:
`tools/xp_v2.py` is never imported by the nightly; recording `xp_v2`
nightly under its own source name is a later wiring item.

- **Item:** S6 (BUILD_PLAN.md Step 6, item M1).
- **Hypothesis:** `xp_v2` — P(start) times the mean of the two conditional
  forecasts, plus the sub term — ranks predicted starters better than `own`
  (mean per-gameweek Spearman among predicted starters) and picks a better
  XI plus captain.
- **Data and sample filter:**
  - *Development set shrinks (ruling 1), stated before any number is
    computed:* `xp_v2` averages `E_xg[pts | start]` and
    `E_bottomup[pts | start]`. Under S4 ruling 2 `xg` cannot be rebuilt for
    2025/26 (FDR and `chance_next_round` are not available pre-deadline), so
    no `xp_v2` candidate can be developed on 2025/26. The development set is
    therefore 2026/27 only: the settled gameweeks for which `own`, `xg`,
    `bottomup` and `minutes` are all recorded (GW5 onward), up to the
    **development cut** = the last settled gameweek on the day S6's first
    code commit is made; that gameweek number is written into the S6 report
    before any number is computed. The validation set is every gameweek that
    settles after the cut, graded only when settled (lockdown guard).
  - *Inputs, all point-in-time through the S2 reader rule:* the recorded
    `xg`, `bottomup` and `minutes` rows (one `predicted` each). Conditional
    forecasts: `E_m[pts | start] = predicted_m / P(start)` for m in {xg,
    bottomup} when P(start) > 0 (every term of both models scales with
    P(start), so this recovers the conditional value exactly); undefined
    when P(start) = 0, where it is multiplied by 0. P(start) = the `minutes`
    row (`start_probability`, the minutes model; never averaged in as a
    points forecast). P(sub) = (appearances − starts) over the same
    four-gameweek window as P(start), scaled by `chance_next_round`, from
    `player_gw` rows before the deadline. E[pts | sub] = the mean realised
    points of sub appearances (minutes > 0, starts = 0) by position over the
    gameweeks before the deadline — measured, not assumed; printed.
  - *Bottomup input:* `bottomup_lambda` if S5's primary test passed and the
    verifier passed S5, else `bottomup`; the report says which.
  - *Penalty term (Step 6 item 2):* P(taker) × team penalties per match ×
    0.78 × GOAL_VALUE[pos], inside both conditional forecasts, with P(taker)
    from the export's `pens_order` decayed when the recorded taker changes
    (order 1 → 1.0 until a different player takes a penalty in `player_gw`
    rows, then 0.5 for the next four gameweeks). Missing input, reported
    not substituted: neither the export nor `player_gw` nor the 2025/26 CSV
    carries team penalties per match (penalty goals are not separated from
    goals; only `penalties_missed` exists), and the API's `expected_goals`
    already includes penalty xG. The term is implemented with its inputs
    declared and evaluates to 0 until a ruled source of team penalties per
    match exists; the development and validation runs state that it was 0.
  - *Filters:* starters = forecast P(start) >= 0.8 from the `minutes` row of
    the same gameweek; never realised minutes. Population = players with a
    forecast in every compared source's snapshot (paired).
  - *Decision metric squad:* our actual 15 per gameweek from `picks`.
- **Comparison:** candidates (Step 6 item 3): equal-weight blend
  (primary), best single model, inverse-MSE weights, inverse-MSE shrunk 50%
  toward equal — weights fitted on the development set only, frozen before
  validation. Equal weights are replaced only if an alternative wins on
  validation by >= 0.02 on the primary metric AND on the decision metric.
  The chosen `xp_v2` is then compared with `own` (Step 6 item 4) and with
  `fpl_ep` (Step 6 item 3, alongside, over the gameweeks both exist; if
  `xp_v2` does not beat `fpl_ep` among starters, the report says so at the
  top).
- **Primary metric (one):** mean per-gameweek tie-corrected Spearman among
  predicted starters, `xp_v2` minus `own`, on the validation set.
- **Secondary metrics (information only):** the decision metric (XI plus
  captain realised points from our 15, S4 definition); MAE; per-position
  Spearman; the same figures on the development set (in-sample, labelled);
  the candidates' validation figures; `fpl_ep` alongside.
- **Bootstrap:** unit = gameweek, 10,000 resamples, 90% CI (percentile),
  paired, seed 20261018 — the S4 harness.
- **Pass threshold:** `xp_v2` beats `own` on the primary metric with the
  90% CI lower bound > 0 on the validation set, AND the validation set holds
  at least G gameweeks from the S4 power calculator at Δ = 0.02 and the s_d
  measured on the development set for this pair (ruling 2). If the validation
  set is shorter than G the result is "inconclusive" and nothing is adopted;
  the pre-registered evaluation is re-run unchanged at the GW10 and GW19
  checkpoints (Step 20) until it is powered, then reported once. Adopting
  `xp_v2` as the decision model needs Boris's acceptance in chat.
- **Acceptance tests (in addition):**
  1. The conditional forecasts: on the recording formula, predicted /
     P(start) equals the sum of the P(start)-free terms (both models, hand
     case); a P(start) of 0 gives xp_v2 = P(sub) × E[pts | sub].
  2. The minutes model is never averaged in as points (mutation red).
  3. Weights are read only from the development set; a mutation fitting on
     the validation set → red. The development cut is read from a frozen
     argument, not from the data.
  4. Point-in-time: every input row for gameweek g is dated before g's
     deadline (verifier check 1b on three gameweeks); the lockdown guard
     refuses an unsettled gameweek.
  5. The penalty term's declared inputs: when a team-penalties source is
     absent the term is exactly 0 and the run prints so; a toy source makes
     it move by P(taker) × rate × 0.78 × goal points.
  6. CLI: `python tools/xp_v2.py --develop --cut <gw>`, `--validate`,
     `--forecast` (prints xp_v2 for the next gameweek from the newest export
     and log, under `--out`; never writes the projection log); nightly
     isolation test as S4; tests in `tests/test_S6.py`.

No re-tuning after viewing results.
