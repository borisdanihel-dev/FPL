## DEFCON removed on both sides (RULING 19 Oct evening, point 1)

- **Outcomes:** S10b's 2024/25 re-score has no DEFCON points. The season
  has no defensive-action counts, so each row is flagged
  `DEFCON missing`, with 0 points. The tool refuses a re-score file with
  any DEFCON points or any row without the flag.
- **Forecasts:** both forecasts' DEFCON terms are 0. The 2024/25 inputs
  carry no counts: no `defensive_contribution` column in `merged_gw.csv`,
  so every canonical row has defcon 0. That makes xp_v2's hit-rate term,
  and bottomup's defcon90 inside own_proxy and own_rebuilt, 0. The tool
  checks the inputs and refuses to run if any count is present.
- **Limitation (stated in the report):** neither side scores DEFCON, so the
  test says nothing about DEFCON. The 2026/27 game pays it; 2024/25 cannot
  measure it.

## Harness: what changes for 2024/25 (no edit to any frozen tool)

- **The drivers.** S6b's `test_2526` and S6c's `test_s6c`
  (`tools/xp_v2_replay.py`) are called unchanged, with the 2024/25 folders,
  odds and re-score. The tool prints its own report, labelled 2024/25, from
  the records they return. Their own printed lines name 2025/26 in fixed
  text, so they are not used.
- **Team names.** S5's `FD_ALIASES` maps football-data's "Ipswich" to
  2026/27's "Ipswich Town". vaastav 2024-25 calls the club "Ipswich". For
  the 2024/25 construction only, the alias is replaced by "Ipswich" →
  "Ipswich", and restored afterwards (a test). Every other 2024/25 name
  maps as it is.
- **Season label.** `backtest.load_2526` labels each row's ruleset
  "2025-26". The label is only used to refuse mixing rulesets, and it does
  not change a number. The report states this.
- **Provenance.** `run.txt` (tools/provenance.py), the inputs' SHA-256 and
  the re-score regenerated by the tool.
